Import a lecture note generated by the Chrome extension `/note` shortcut into the vault.

Usage: /lecture-note <paste the markdown content from the Chrome extension>

The user will paste raw markdown generated by the Chrome extension. Your job:

## 1. Parse and validate

- Extract frontmatter fields: tags, type, course, section, lecture, instructor (may be absent), date_watched, status, confidence, cert, platform
- Extract the lecture title from the H1 heading (which may be `# Lecture N - Title` or just `# Title` when the source had no lecture number)
- Note the `cert:` value — it drives Section 1.5 (target folder) and Section 2 (tag handling) below
- Note the `platform:` value — preserved into the final note as-is, no validation
- Backward compat: if frontmatter has no `cert:` field (legacy notes from the pre-generalization prompt), infer from tags as before:
  - `aws + saa-c03` → `cert: saa-c03`
  - `kubernetes + cka` → `cert: cka`
  - otherwise → ask the user

## 1.5. Validate cert and pick target folder

Use the `cert:` value to determine the target folder under `$WIKI_VAULT/Learning/`.

List actual folders under `Learning/`:

```bash
ls "$WIKI_VAULT/Learning/"
```

Apply the first matching rule:

| Condition | Action |
|---|---|
| `cert: <abbrev>` matches a folder name (case-insensitive, allowing common variants like `saa-c03` ↔ `AWS SAA`) | Target folder = `Learning/<matched folder>/` |
| `cert: <abbrev>` does not match any folder | Show available folders, ask: "Cert `<abbrev>` doesn't match any folder under `Learning/`. Available: [list]. Which folder should this lecture go to?" Wait for answer. |
| `cert: unknown` | Slugify the course title (lowercase, spaces → hyphens, non-alphanumeric stripped, runs of hyphens collapsed, leading/trailing hyphens trimmed). Ask: "This note isn't tagged for a cert. Save under `Learning/<course-title-slug>/`? (y / n / custom path)". On `y`, create the folder if missing. On `n`, ask for the custom path. |

Never write to a folder that doesn't exist without confirmation.

## 2. Fix issues

- **Frontmatter:** Ensure required fields are present (type, course, section, date_watched, status, confidence, cert, platform). `lecture` and `instructor` are optional — `lecture: null` is valid for unnumbered lectures, and `instructor` is omitted entirely when not visible on the source page. Fill in any missing required fields from context; do not fabricate `instructor` or `lecture`.
- **Tags:** Behavior depends on `cert:`:
  - **Cert content (`cert ≠ unknown`):** Remove any tags not in the vault's tag registry or standard cert tags. Fix formatting.
  - **Non-cert content (`cert: unknown`):** Accept the topic tags as-is. Still validate against the vault tag registry — flag (don't reject) unrecognized tags so the user can decide whether to propose them via `/wiki tag propose`.
- **SR cards:** If a `# Spaced Repetition Cards` block is present (cert content), review each card against quality rules:
  - Remove trivia cards (counts, step numbers, install procedures)
  - Remove cards testing things you'd just Google
  - Keep cards testing exam-relevant decisions, distinctions, defaults, security implications
  - Every card must pass: "Could this appear on the exam or help answer an exam question?"

  If the SR Cards block is absent (non-cert content with `cert: unknown`), skip this step entirely. Note in the Step 5 report: `No SR cards (non-cert content)`.
- **Connections:** Verify wiki-links point to lectures that actually exist in the cert folder. Remove broken links.
- **ASCII diagrams:** Any ASCII art, box-drawing, or pre-formatted visuals (typically under `## Diagrams / Visuals`) must be wrapped in a fenced code block with the `text` language tag (e.g. ```` ```text ````). This preserves monospace alignment in Obsidian without triggering syntax highlighting. If the incoming note has the diagram as indented text or unfenced, wrap it.
- **Code examples:** Every code block (typically under `## Code / Configuration Examples`, but anywhere else too) must be wrapped in a fenced code block with the appropriate language tag. Pick the tag that matches the content:
  - `bash` — shell commands, CLI examples (`aws`, `kubectl`, `yum`, etc.), any script starting with `#!/bin/bash`
  - `json` — JSON policy documents, API payloads, AWS IAM policies
  - `yaml` — CloudFormation, Kubernetes manifests, GitHub Actions
  - `hcl` — Terraform
  - `python`, `go`, `js`, `ts`, etc. — language-specific code
  - `text` — mixed annotation-only blocks (e.g., URL examples with `# comments` but no real code), or when no language fits
  - If the incoming note has the code as indented text (4-space prefix), unfence-unwrap and rewrap with the correct tag. Also convert arrow annotations like `<- comment` to shell-style `# comment` when inside a `bash` block so they don't break syntax highlighting.
- **Content:** Light cleanup only — fix obvious errors, don't rewrite.

## 3. Create the file

- Filename:
  - If the lecture has a number: `Lecture NN - Title.md` (zero-padded to 2 digits if number < 100)
  - If the lecture is unnumbered (`lecture: null` in frontmatter): `<Title>.md` (keep capitals and spaces, strip filesystem-unsafe characters: `/`, `\`, `:`, `?`, `*`, `<`, `>`, `|`, `"`)
- Write to `$WIKI_VAULT/<target folder from Section 1.5>/<filename>`
- If the file already exists, warn the user before overwriting

## 4. Update the _Index.md

**If `_Index.md` does not exist in the target folder** (typical for non-cert folders that haven't been initialized via `/course-import`): skip this entire section. Do not auto-create an `_Index.md` from a single lecture — that's the `/course-import` job. Note in the Step 5 report: `No _Index.md in target folder; lecture written but not indexed.`

**Otherwise, proceed with the merge logic below:**

Check whether the `_Index.md` Lectures table has a Duration column (6 columns) or not (5 columns).

**If the lecture already exists in the index (added by a prior `/course-import` run):**
- Find the row: match by lecture number first; fall back to title match if the row has no lecture number
- Update its Status to `complete`; preserve the existing Duration value
- Do not add a duplicate row

**If adding a new row to a 6-column table:**
```
| NN | [[Lecture NN - Title]] | Section Name | — | complete | — |
```

**If adding a new row to a 5-column table (pre-course-import):**
```
| NN | [[Lecture NN - Title]] | Section Name | complete | — |
```

Update the Sections covered checklist if this lecture completes a section.

**Update remaining scalars** (only if `remaining_count` exists in `_Index.md` frontmatter, and only when adding a new `complete` row — skip this block if you updated an existing row):
- Read the completed row's Duration value
- Decrement `remaining_count` by 1 (minimum 0 — do not go negative)
- If Duration was a numeric value (not `—`), parse the integer and decrement `remaining_minutes` by that amount (minimum 0)
- Write the updated value(s) back to frontmatter

After creating the file, briefly report:
- File created at [path]
- Cards kept / cards removed (with reasons for removals)
- Any fixes applied
- _Index.md updated
- (If applicable) `No SR cards (non-cert content)`
- (If applicable) `No _Index.md in target folder; lecture written but not indexed.`
- (If applicable) `Cert folder picked: <folder>` when the user had to confirm a non-default folder
